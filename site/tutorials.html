Tutorials

From zero to a trusted agent in four steps.

Runnable walkthroughs against the real model — the same SurrealQL the flows use. Load the schema and seeds (see scripts/surreal_smoke_test.sh), then follow along. Full versions in docs/tutorials.md.

Tutorial 1

Register an agent

Create the identity, provision its lifecycle, and activate it. The agent is now a first-class, governed identity.

CREATE agent_identity:acme_bot CONTENT {
  subject: "agent:acme-bot", status: "active"
};
CREATE agent_lifecycle CONTENT {
  identity: agent_identity:acme_bot,
  state: "provisioned", entitlements: ["agent.identity"]
};
UPDATE agent_lifecycle SET previous_state = state, state = "active"
WHERE identity = agent_identity:acme_bot;
Tutorial 2

Issue a credential

Record a Verifiable Credential — a credential subject plus a vc verification, linked to the agent.

CREATE credential_subject CONTENT {
  identity: agent_identity:acme_bot,
  subject_id: "agent:acme-bot",
  claims: { capabilities: ["research"] }
};
LET $v = (CREATE ONLY identity_verification CONTENT {
  identity: agent_identity:acme_bot, method: "vc",
  verifier: "did:web:identity.agennext.dev",
  status: "verified", verified_at: time::now()
});
RELATE agent_identity:acme_bot->verified_by->$v.id;
Tutorial 3

Rotate a key

Add a new DID verification method, make it the only authentication key, and retire the old one (kept for history).

LET $k2 = (CREATE ONLY verification_method CONTENT {
  document: did_document:acme_bot,
  id: "did:web:agents.agennext.dev:acme-bot#key-2",
  type: "Multikey", controller: "did:web:agennext.dev",
  publicKeyMultibase: "z6MkNewKeyMaterial"
});
RELATE did_document:acme_bot->has_verification_method->$k2.id;
UPDATE did_document:acme_bot SET
  verificationMethod += $k2.id,
  authentication = [$k2.id];
Tutorial 4

Verify trust before acting

A downstream service checks three things at once: the agent is active, has a verified credential, and operates in a trust domain. Any failure → refuse.

SELECT
  (SELECT VALUE state FROM ONLY agent_lifecycle
     WHERE identity = agent_identity:acme_bot LIMIT 1) AS state,
  count(SELECT id FROM identity_verification
     WHERE identity = agent_identity:acme_bot
       AND status = "verified") AS verified_count,
  ->operates_in->trust_domain.name AS trust_domains
FROM agent_identity:acme_bot;

Trust is earned, verified, and revocable.

Register, credential, rotate, verify — then the same lifecycle lets you revoke and de-provision when the agent's job is done.
